## 📦 Модель распространения (как у OpenRA)

В играх с открытым движком (OpenRA, fheroes2, GZDoom, DXX-Rebirth) действует строгое разделение между кодом и ассетами:

1. **Исходный код движка** открыт под лицензией GPL v3. Его можно свободно собирать, модифицировать и распространять.
2. **Игровые ресурсы** (`.big`-архивы, текстуры, 3D-модели, звуки, музыка, карты и ролики) защищены авторским правом Electronic Arts. Репозиторий **не содержит** проприетарных файлов игры.
3. **Модель «Bring Your Own Game» (BYOG)**:
   - Игрок легально приобретает копию игры (например, *Command & Conquer: The Ultimate Collection* в Steam или EA App, либо использует оригинальные диски).
   - Пакет игры (Flatpak/Flathub, AppImage, `.deb`) устанавливает только скомпилированный бинарный файл движка.
   - При первом запуске движок находит папку с игрой автоматически через библиотеки Steam (`~/.local/share/Steam/steamapps/common/...`) либо предлагает выбрать каталог с Zero Hour вручную.
   - Оригинальные `.big`-файлы монтируются исключительно для чтения.

## 🔬 Инженерные заметки: замеры и оптимизации

В ходе локального профилирования рендера Command & Conquer Generals Zero Hour на тестовом стенде (Ubuntu 24.04, NVIDIA GeForce RTX 3090 24 GB) были изолированы ключевые факторы производительности:

### 1. Задержка презентации: Wayland и X11

При запуске клиента в сессии Wayland через прослойку XWayland зафиксирована существенная задержка передачи кадров:

| Метрика | Сессия Wayland (XWayland) | Чистая сессия X11 | Разница |
| :--- | :--- | :--- | :--- |
| Время кадра (`total`) | ~78–135 мс | **11.1 мс** | Ускорение в **7–12 раз** |
| Задержка `vkQueuePresentKHR` | 40–62 мс | **0.05 мс** (47–52 мкс) | Снижение задержки в **800 раз** |
| CPU draw-путь | 13–52 мс | **8.6 мс** | Быстрее в 2–6 раз |
| Частота кадров в HUD | 7–13 FPS | **20 FPS** (время кадра 11.1 мс) | Плавный отклик |

**Вывод**: в сессии Wayland замеренная задержка презентации стабильно составляла 40–62 мс, тогда как в X11 падала до 0.05 мс (наиболее вероятная причина – накладные расходы очередей XWayland-композитора). Для максимальной производительности на текущем этапе рекомендуется запуск в сессии X11.

---

### 2. Отсечение тайлов рельефа по пирамиде видимости (Frustum Culling)

В цикле отрисовки рельефа тайлы карты перебирались целиком на каждом шейдерном проходе без предварительной проверки видимости камерой:

| Параметр | Без отсечения | С отсечением AABB по `Cull_Box` | Эффект |
| :--- | :--- | :--- | :--- |
| Вызовов отрисовки на кадр | 1380 → 771 | **432** | Минус **948 вызовов** |
| Вызовов рельефа (`catTerrain`) | 624 → 508 | **172** | Сокращение на **72%** |
| Время CPU на draw | 52 мс | **14.6 мс** | Экономия **37 мс** на кадр |
| Время кадра | 134 мс | **81 мс** (Wayland) / **11 мс** (X11) | Чистая прибавка производительности |

**Решение**: проверка ограничивающего параллелепипеда тайла рельефа (с полным диапазоном высот карты) через `CameraClass::Cull_Box()` в базовом цикле и в дополнительных проходах. Экспериментальный патч отсечения тайлов рельефа по камере (описан ниже в предложениях для апстрима).

---

### 3. Батчинг двумерного интерфейса по страницам текстурных атласов

Оригинальный интерфейс сбрасывал двумерный рендер при каждой смене объекта изображения:

- Оптимизация `same2DTexture()`: батч остаётся открытым для разных объектов `Image`, если они используют один и тот же файл текстуры (одинаковую страницу атласа).
- Охват `winRepaint()`: проход отрисовки всех окон держится в едином батче, исключая холостые переключения состояний между кнопками и глифами шрифтов.
- Сокращение вызовов: с 1380 до 885 вызовов на кадр в тестовой сцене.

---

### 4. Исправление заливки цветом игрока («цветофильтр» на карте)

- **Симптом**: Рельеф в игре заливался прямоугольной цветной дымкой (красной у Китая, синей у США, фиолетовой у GLA).
- **Причина**: Функция `W3DScene::renderStenciledPlayerColor()` рисует полноэкранный квад в цвете локального игрока и маскирует его трафаретным буфером (stencil) поверх перекрытых объектов. В Vulkan-пайплайне трафаретный тест не был сконфигурирован, в результате чего квад рисовался без маски на весь тактический вид.
- **Решение**: Вызов `DX8Wrapper::Has_Stencil()` на Linux возвращает `false`, что направляет движок по штатному нетрафаретному пути `flushOccludedObjects()`.

---

### 5. Полноцветная миникарта и 24-битные поверхности

- **Симптом**: Чёрная миникарта у США при старте матча.
- **Причина**: Выбор формата текстуры радара предпочитал 24-битный `R8G8B8` (3 байта на пиксель), тогда как функция `SurfaceClass::Draw_Pixel()` обрабатывала только 1, 2 и 4 байта (запись пикселей рельефа была пустым действием).
- **Решение**: Добавление 3-байтового регистратора BGR в `Draw_Pixel()` и приоритизация 32-битного формата `X8R8G8B8` в списке форматов радара.

## 🚀 Как запустить игру на Linux

### Вариант 1. Готовые пакеты из апстрима Reforged (рекомендуется)

1. Установите оригинальную игру в Steam (*Command & Conquer: The Ultimate Collection*).
2. Скачайте свежий релиз из [репозитория Reforged](https://github.com/olcayseygan/CnCGeneralsZH-Reforged/releases/latest) (доступны AppImage, Flatpak, `.deb`, `.rpm`, Arch).
3. При запуске укажите путь к каталогу с файлами игры (или позвольте движку найти библиотеку Steam автоматически).
4. **Рекомендация по сессии**: выбирайте сессию «GNOME on Xorg» / X11 на экране входа для минимальной задержки презентации.

### Вариант 2. Сборка из исходников

```bash
# Клонирование канонического апстрима с Vulkan/SDL3 бэкендом
git clone https://github.com/olcayseygan/CnCGeneralsZH-Reforged.git
cd CnCGeneralsZH-Reforged

# Сборка на Linux
./build-linux.sh Release generals
```
